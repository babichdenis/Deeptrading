# ML-MTF-1 — обучение сочетаний функций на нескольких таймфреймах

Назначено архитектором 2026-10-12 всем трём builders. Это активная линия вместо дальнейшего перебора BATCH15. Каждый выполняет всю свою ветку: реализация → focused tests → данные → исследование → DELIVERY, без отдельного разрешения на каждый шаг. Ориентир — содержательный блок примерно на 2 часа с checkpoint/resume; это не обещание окончания вычислений за 2 часа. Не останавливаться после схемы или первого теста. Передачи DATA_READY / MODEL_READY через append-only chat.md под собственной .chat-write.lock; потребители продолжают автоматически. ACK означает получение, а не выполнение.

## Цель и уже существующая основа
Выявить, какие СОЧЕТАНИЯ значений/изменений функций и голосов на разных ТФ связаны с последующей разметкой, и проверить экономический результат этих сочетаний на более поздних датах. Пример владельца RSI/MACD/bias не является предписанным правилом. Одиночные функции нужны как сравнительная база; результат ветки — обучаемый воспроизводимый конвейер и измеренное добавочное качество взаимодействий.

Найдено в коде: scripts/label_votes.py уже соединяет разметку и 7 голосов; reports/label_votes.parquet существует. scripts/label_backfill.py описывает реальные таблицы labels и ideal_trades; app/models/signals.py — signals.features и strategy_runs; app/models/signal_trace.py — trace/context и outcomes; app/services/ml_meta.py — multi-TF features и метаобучение; app/engine/candlehub.py и indicatorhub.py — закрытые бары/индикаторы. Сначала переиспользовать существующие вычисления, не писать ещё один RSI/ресемплер/движок.

Существенное расхождение: label_votes.py:96–116 выбирает upper прежде lower при двойном касании, app/engine/labeling.py:triple_barrier выбирает stop-first. Старый parquet без provenance нельзя объявлять каноническим обучающим набором. states_for старого скрипта также отдаёт BUY при наличии обоих направлений в lookback; не переносить это молча. Исправление в этой ветке — версионированный адаптер с однозначными правилами, старые артефакты остаются неизменными.

## Общий контракт данных v1 (фиксирован сейчас)
- Universe — весь текущий elite31, без отбора по результатам; missing HHRU/частичное покрытие явно. Состав сохраняется до обучения, current-universe bias остаётся ограничением. Использовать имеющийся snapshot B1 research_core_v2/b1/20261011T1947Z/snapshot/csv и read-only БД для признаков/разметки. История по 2026-10-08 включительно, будущие даты пока не использовать.
- Наблюдение — каждый закрытый 1m бар с ключом row_id=sha256(figi,decision_ts,dataset_version); ts свечи-начала преобразовать в фактическое время закрытия. Исходы отдельно: features.parquet и targets.parquet, объединение строго по row_id. Шардинг по ticker допустим, manifest перечисляет файлы. Обязательные поля features: row_id,figi,ticker,decision_ts,feature_max_available_ts,feature_schema_version и признаки. Targets: row_id,label,label_cfg_hash,label_status,label_end_ts. Неизвестный/незрелый исход НЕ neutral/0.
- Primary target: canonical triple_barrier на закрытых 5m барах, take=1.5ATR, stop=1.5ATR, max_bars=24, atr_period=14. Это направленная close-anchored метка, не доходность исполнимой сделки. Supervised строки только на закрытиях 5m, соответствующих этой метке; сохраняем per-minute features для последующего replay. Внутрисессионные targets: если до закрытия сессии барьер/горизонт не завершён — CENSORED, не ноль. Никакой перенумерации горизонта через пропуски. Метка -1 при двойном касании означает консервативное соглашение для long, не доказательство прибыльного short. Zigzag/ideal_trades только отдельная описательная цель, никакие pivot/oracle поля в X.
- B1 проверяет фактический cfg_hash и семантику labels. Совпадающие mature записи переиспользовать; отсутствующие/несовместимые вычислять тем же labeling ядром в НОВЫЕ offline targets, без записи в БД. label_end_ts — время, когда исход стал известен (закрытие соответствующего бара, не его начало).
- ТФ признаков: 1/5/10/30/60 минут. На каждом: доступные RSI14, MACD12/26/9 histogram и его изменение, EMA50 distance/slope, ATR14/price, volume ratio20; bias по существующей compute_bias с зафиксированным периодом50. Использовать registry/параметры, явно записать нормировки. Добавить существующие индивидуальные голоса, возраст последнего голоса, quorum и разногласия, version/config/source. Полный список в feature_schema.json, без перебора новых периодов. Необязательные реально отсутствующие источники отразить в coverage, не ждать их бесконечно: восстановить доступные голоса из существующего ensemble на snapshot. Не сводить все функции к семи булевым голосам.
- Доступность: source bar END <= decision_ts, forming bars запрещены; warmup по реальным требованиям. Существующие stored features переиспользуются только при установленной версии/timing. Пропуск, неготовность и настоящий ноль различаются; голос действует только в сохранённом config lookback, противоположные события — last-event semantics + conflict flag, без BUY priority. Missingness не закрывать синтетической ценой/ATR. Full-window coverage eligibility из V2 использует будущие даты и НЕ применяется к историческим решениям. Допуск в конкретный день только из доступной на тот момент истории.
- Общие даты всех тикеров: train до 2026-05-31, validation 2026-06-01..2026-07-31, final evaluation 2026-08-01..2026-10-08. Из предыдущего раздела удалить строки, label_end_ts которых достигает следующего; дополнительно embargo 120 минут перед границей. Препроцессинг/пороги fit только train/validation по назначению. Все прежние периоды уже исследовались проектом: final evaluation — temporal out-of-training, НЕ нетронутый holdout проекта.
- Манифест: actual rows/classes/tickers/dates/missing/label configs, code/input/config SHA256, versions/seeds, тайминг, исключения. Новые артефакты backend/reports/architect_20261012/ml_mtf_1/bN/<run_id>/, пути в передачах абсолютные. Готовность обозначает наличие manifest и файлов, не только текст.

## Автономность и границы
Каждый выполняет всю ветку и принимает передачи других без ручного разрешения. Отсутствие чужих файлов не мешает собственному CLI/fixtures/tests. Зависимый реальный run ждёт артефакт, не имитируется. При блокере — точный файл/ошибка/предлагаемое совместимое решение в chat.md и продолжение независимой части. Схему не менять молча; добавлять совместимые поля, breaking conflict направить архитектору. Чужие файлы не редактировать. Разрешены focused tests и bounded offline research данной ветки, read-only production DB. Без реальных orders, запуска бота, deploy, broker APIs, массового backfill и ручных правок свечей. Широкие suites не нужны. Старые результаты неизменны.

V2 сохраняется как предыдущее исследование. B1/B3 последние DELIVERY прочитаны. Остались неверные широкие утверждения: «структурная безубыточность недостижима» не следует из этих15 правил; B10 gross0.1634% выше дешёвых roundtrip costs~0.14%, его cheap-net положителен, expensive-net отрицателен; расходы дневных сделок не считать пренебрежимыми. Это уточнения чтения, не новая очередь переписывания старых отчётов. Coverage-filter19/31 V2 использует весь будущий год, поэтому не point-in-time universe для ML.
