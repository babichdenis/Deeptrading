# ADR-0001: Hermetic baseline для CI (разделение тестов на контуры)

- **Дата:** 2026-10-01
- **Статус:** принято (владелец подтвердил)
- **Источник:** `docs/roadmap/PROJECT_AUDIT_2026-09-30.md`, P0.4 (+ P0.1–P0.3, P0.5)

## Контекст

Аудит показал: полный прогон давал `883 passed, 12 failed, 52 errors`, причём
большая часть errors — отсутствие локальных research-файлов в `backend/reports/`
(`entry_confluence.json`, `entry_quality.json`, `vote_attribution.json`,
`imoex_*`, манифесты). Эти файлы не входят в checkout, но тесты требовали их
без skip/marker. Итог: число «весь suite прошёл» зависело от конкретной машины
и её каталога `reports` — такой baseline невозможно защитить CI.

Дополнительно: `test_research_pack.py` падал из-за отсутствия живых свечей
в БД, CI поднимает пустой `postgres:16`.

## Решение

1. **Три контура тестов** — маркеры в `backend/pytest.ini`:
   - `artifact` — требуют локальные research-файлы `backend/reports/`
     (в git не входят, машино-зависимы) → 7 файлов помечены;
   - `integration` — требуют живых данных БД live-стенда (`.2`)
     → `test_research_pack.py`;
   - hermetic/unit — всё остальное, основной контур.
2. **CI гоняет только hermetic:** `pytest -q -m "not artifact and not integration"`.
   Зелёный baseline — **900 passed / 0 failed**.
3. Пункт P0.5: на `(path, method)` разрешён **ровно один** обработчик.
   `tests/test_route_uniqueness.py` падает при дубликатах.

## Альтернативы

- **Генерировать фикстуры `reports/` перед прогоном** — дорого, медленно,
  плодит дублирование артефактов в коде; отвергнуто.
- **Держать один общий suite и чинить все 12 failures** — часть падений
  является ожидаемым следствием отсутствия живых данных, «лечить» их
  ослаблением assert'ов хуже, чем честно их выделить.
- **`--ignore` вместо маркеров** — маркер даёт явный opt-in/opt-out на уровне
  теста и документирует причину, `skipif` прячет зависимость в коде теста.

## Следствия

- Baseline воспроизводим на любой машине и в CI.
- Локальный полный прогон (`pytest tests -q`) остаётся доступен и показывает
  ожидаемые флаки по данным БД .2.
- Новые machine-dependent тесты обязаны получать маркер, иначе сломают CI.
