# ADR 0002 — Семантика таймфреймов и момент доступности бара

- **Статус:** принято (решение владельца, 2026-10-01, коммит `1364705`)
- **Заменило:** молчаливую договорённость, которая в разных модулях читалась
  по-разному и была причиной look-ahead в реплее
- **Канон:** `docs/roadmap/PROJECT_AUDIT_2026-10-01.md` §P1.3/P1.5,
  `MEMORY.md` §«КАНОН ТФ-АГРЕГАЦИИ»

## Контекст

Метка свечи времени T-Invest, нативных ТФ-баров и нашей БД — **начало бакета**.
Это подтверждено сверкой с нативными барами T-Invest (10m — 102/102,
1h — 18/18) и заморожено тестом `tests/test_aggregators_parity.py`, который
требует идентичности ряда у всех агрегаторов.

Пока это нигде не было записано, каждый новый модуль выбирал свою семантику.
Реальные последствия:

- `app/engine/candlehub.py` в верхнем docstring утверждал `ts` = момент закрытия
  и `(T - tf, T]`, тогда как код с самого начала строил `[T, T+tf)`. Разработчик,
  поверивший docstring, реализовал бы consumer с look-ahead.
- Меры Universe отбирали бары по `ts <= as_of`; при метке=начало это включало
  бар, ещё не закрытый на момент `as_of`.

## Решение

### 1. Метка = начало бакета

Бар с меткой `T` и таймфреймом `TF` описывает полуинтервал **`[T, T+TF)`**,
открывается в `T`, закрывается в `T+TF`. Границы бакетов — от глобальной
UTC-сетки (кратно `TF`), пустые бакеты не существуют.

Метка 1m-свечи подчиняется тому же правилу: 1m-бар с меткой `T` покрывает
минуту `[T, T+1)`.

Никаких новых агрегаторов с END/ceil-семантикой (метка по закрытию) не
заводим: это размножило бы расхождения.

### 2. Когда бар закрыт и когда доступен

| Событие | Момент |
|---|---|
| Бар закрыт | `bar.ts + TF` |
| Бар доступен стратегии/мерам | `bar.ts + TF` (не раньше) |
| Бар записан в БД как «закрытый» | `bar.ts + TF` |
| Видимость для расчёта на `as_of` | `bar.ts + TF <= as_of` (включительно) |

Граница **включительная**: на самом моменте закрытия бар уже виден.

### 3. Граница `as_of`

Везде, где есть `as_of` (меры Universe, сид реплея, выборка баров), отбор
строго по закрытию:

```
bar.ts + TF <= as_of
```

Фильтр `ts <= as_of` **неверен** при метке=начало: он включал незакрытый бар.
Это не косметика — на replay-старте ровно в `T` рантайм подглядывал в минуты,
которые ещё не видел.

Канон реализован в `app.bot.universe.bars.bar_is_visible` / `bar_close_ts`,
применён в `features` / `volatility` / `trend`, в `BULK_TAIL_SQL` и в
предфильтре FIGI. Заморожено `tests/test_universe_v2_as_of_boundary.py`.

### 4. Partial-бар

Формирующийся бар (partial) **не доступен** стратегии и не попадает в
snapshot: бар доступен только после закрытия (§2). В `CandleHub` partial
живёт отдельно от `_closed`.

### 5. EOD, гэпы, flush

- **Гэп внутри бакета** даёт короткий, но валидный бар: пропуск минут не
  отменяет закрытие по времени. Плотность — забота потребителя.
- **Хвостовой неполный бакет** (последний в потоке, дальше свечей не будет)
  не эмитится сам — его закрывает `finalize()`: конец реплея, EOD, обрыв.
  Без `finalize()` последний бар дня (граница 00:00 UTC при закрытии торгов
  ~20:50 UTC) просто потерялся бы.
- **Опоздавшая минута** (`ts` меньше последней) — это дыра в 1m-ряду: вставляется
  на своё место, производные ТФ перестраиваются из 1m-истории (rebuild).

### 6. Две конвенции доступности — и почему они разные

В проекте сосуществуют две шкалы времени, и это **не** ошибка, а явное решение:

1. **Шкала расчёта** (`as_of` в чистых мерах) — стенное время доступности.
   Бар с меткой `T` доступен в `T+TF`.
2. **Шкала рантайма** (`runtime._is_closed`) — «бар с меткой `ts` отдан в
   работу в момент `ts`». Сравнение `now >= c.ts`.

Расхождение в одну минуту на 1m существенно по двум причинам:

- Основную гарантию закрытия даёт **источник**: `feed` отдаёт только закрытые
  бары (`mds.candles.waiting_close()`), а незакрытые обновления отсекает
  гейт свежести по wall-clock ниже по потоку. `_is_closed` — страж от
  backfill'а и исторической перемотки, а не определение полноты интервала.
- Сменить `_is_closed` на формально строгое `now >= c.ts + ТФ` **нельзя
  изолированно**: в реплее `_bot_now()` возвращает метку последней поданной
  свечи, поэтому stricter-вариант отсёк бы все бары и бот не торговал бы вовсе
  (parity 0/3). Такой перенос = смена шкалы реплей-часов, то есть отдельное
  решение владельца с отдельной проверкой паритета.

Следствие для Universe: `select_screened_universe` в `_startup` получает
`as_of = _replay_from or _bot_now()`, то есть снимок **до** старта реплея.
Поэтому отбор не может заглянуть в окно реплея даже при строгой границе.

## Альтернативы

- **Оставить `ts <= as_of`** (отвергнуто): проще и совпадает с «интуицией
  автора», но при метке=начало систематически включает незакрытый бар. Именно
  этот вариант породил P1.3.
- **Перевести метку на закрытие (END/floor)** (отвергнуто): не совпадает с
  T-Invest и нативными барами (проверено 102/102), ломает паритет с биржей и
  переписывает всю БД-семантику.
- **Сменить `_is_closed` на строгую форму** (отложено): корректно по §2, но
  требует перевода реплей-часов на `ts + TF` и перепроверки паритета. См. §6.

## Последствия

- Новый код, принимающий `as_of` или агрегирующий ТФ, обязан использовать
  `bar_is_visible`, а не сравнение `ts <= as_of`.
- Новый агрегатор ТФ обязан попасть в `tests/test_aggregators_parity.py`.
- Правка `_is_closed` без смены шкалы реплей-часов запрещена — это регресс,
  который выглядит как «бот перестал торговать».
