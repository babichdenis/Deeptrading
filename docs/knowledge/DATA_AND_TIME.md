# Данные, время и качество

## Источник данных

Исторический потребитель читает PostgreSQL. Загрузка идёт через проверку покрытия и получение недостающего из поддерживаемых источников, а не прямое скачивание внутри стратегии. T-Invest и MOEX — источники со своими семантикой и качеством; сравнение без одинаковых инструмента, интервала, времени и шкалы цены некорректно. `ensure` не означает, что любой пустой ответ доказывает отсутствие торгов.

## Минутные макроряды

Из каталога `backend` команда `python -m scripts.sync_macro_candles` выполняет загрузку MOEX ISS в PostgreSQL через штатный upsert свечей. `--history-start` задаёт начальную границу с часовым поясом. `--futures-contract` можно указать несколько раз, по точному коду контракта. IMOEX сохраняет существующий идентификатор, остальные ряды различаются по площадке и коду инструмента. Стратегия читает историю через Candle Hub.

Для повторения контрольного запуска на отдельной PostgreSQL:

```text
python -m scripts.sync_macro_candles --history-start 2026-10-09T07:00:00Z --as-of 2026-10-09T07:03:00Z --futures-contract BRX6 --futures-contract NGV6 --futures-contract SiZ6
```

Постоянный сбор поддерживает `--period-seconds`; исторический `--as-of` с ним несовместим. Команда использует соединение с PostgreSQL из настроек проекта. Для текущего сбора можно повторить аргумент `--futures-asset` для BR, NG и Si. Для каждого актива сборщик берёт два ближайших по последней дате торговли контракта из текущего каталога ISS, сохраняет их под разными ID и публикует ошибки каталога отдельно. Исторический `--as-of` допускает только явные коды из исторического снимка. До включения постоянного сбора требуется проверить перекрытие с действующими задачами IMOEX.

Запуск продолжает загрузку от последней сохранённой закрытой минуты. Пропуски внутри истории проверяются отдельно через Candle Hub и независимые сведения о сессии. Статус `received` показывает полученные свечи, `no_rows` — пустой результат, `partial` — отклонённые при записи свечи, `error` — сбой обработки ряда. Получение и запись свечи не устанавливают, когда её значения впервые были доступны историческому решению. Для этого нужен журнал версий и времени получения.

## Канон времени

- Внутреннее время UTC, timezone-aware; Москва используется на границе UI и явно заданных сессионных правил.
- Метка свечи `T` — **начало** бакета `[T, T+TF)`, границы по UTC-сетке.
- Бар доступен расчёту на `as_of`, когда `T + TF <= as_of`.
- Partial-бар не становится закрытым только из-за наличия строки. Новые агрегаторы с END/ceil-семантикой запрещены.
- Для мер использовать `bar_is_visible` / `bar_close_ts`. Текущую runtime-шкалу `_is_closed` нельзя изолированно заменить: feed и replay clock должны меняться согласованно.

Основание и важное различие шкал расчёта/runtime: [ADR-0002](../adr/0002-timeframe-semantics.md). Эта запись заменяет старую строку MEMORY «метка = закрытие».

## Пропуски и достоверность

Различать отсутствие наблюдения, отсутствие торгов, недоступный источник, повреждённый ответ и невалидные цены. Missing/UNKNOWN не превращать в нулевой результат. Разреженный бакет может закрыться по времени, но это не доказывает пригодность его плотности для конкретного потребителя. Хвостовой finalize и partial-флаги сохраняют смысл; completeness проверяется контрактом потребителя.

Цены, масштаб и corporate actions требуют отдельной проверки. Корректный JSON и монотонные timestamps не доказывают согласованность рядов разных ТФ. Старые гипотезы о сплитах и последние заявления о дефектах не становятся установленными фактами без первичного источника и артефакта сравнения.

### Проверка смешения минутных и пятиминутных свечей

Команда `python -m scripts.audit_candle_interval_overlap` из `backend` принимает `--manifest` с контрольными инструментами, `--start` и `--end` с часовыми поясами. JSON показывает число минутных свечей на пятиминутной сетке и полные совпадения OHLCV с отдельно хранимыми 5m. Отдельные совпадения возможны в корректной истории; массовое совпадение требует сверки с независимым источником.

Для проверки дневного покрытия сравнивайте полные соседние сессии через `--context-start` и `--context-end`. Данные и эталоны при этом читаются без записи. Контрольный пример на .8:

```text
python -m scripts.audit_candle_interval_overlap --manifest reports/architect_20261115/hub_transfer_2026-08_r1/manifest.json --start 2026-11-16T11:00:00Z --end 2026-11-16T15:00:00Z --context-start 2026-11-08T21:00:00Z --context-end 2026-11-16T21:00:00Z
```

## Где закреплён сквозной контракт

[PIPELINE_TESTING](../PIPELINE_TESTING.md): источник → валидация/транзакция → БД → hub → исследовательское исполнение. Изолированная тестовая БД обязательна для его PostgreSQL-контура. Список инвариантов и допустимых статусов брать из этого документа и соответствующего кода; историческая ручная правка одной свечи не заменяет постоянной защиты на границе записи.


### Единицы объёма и фильтр оборота — ARCH234
Т-Инвестиции документируют candle.volume в лотах ([MarketData](https://developer.tbank.ru/invest/services/quotes/marketdata), [архив](https://developer.tbank.ru/invest/services/quotes/get_history)). В текущей таблице candles у volume нет единицы/происхождения; существующие загрузчики T-Invest и MOEX пишут исходное поле напрямую. Поэтому close×volume нельзя автоматически объявлять рублёвым оборотом, а весь исторический volume нельзя умножать на текущий lot. MoveSelectConfig.min_turnover>0 теперь прекращает отбор с явной ошибкой недостающего подтверждённого оборота; fallback на другой universe для этой ошибки запрещён. Реализация самого фильтра требует источника RUB turnover и наблюдаемого as_of.


### Проверка отсутствующих минут — 2026-11-16

После успешного GetCandles без свечи сохраняем `source_absence_observed`, а не автоматически `no_trading`. Для недельного исследования проверены 52 окна: все 61 спорная минута отсутствуют в повторном ответе источника (ARCH484). Заполнение искусственными свечами не выполнялось.

[Сервис исторических рыночных данных](https://developer.tbank.ru/invest/services/history-md/head-history-md) описывает архивы обезличенных сделок и минутных свечей. Это следующий источник проверки; доступность конкретных архивов и полнота ленты ещё не установлены. [GetLastTrades](https://developer.tbank.ru/invest/services/quotes/marketdata) описывает ленту последнего часа и не заменяет недельный архив. Старое описание пропусков стрима при отсутствии сделок не доказывает обратное утверждение для нынешнего GetCandles.

- Приёмка истории версий макросвечей: для одной минуты сохранить исходную свечу и исправление с разным временем доступности. Запрос между этими отметками должен вернуть исходный OHLCV, после исправления — исправленный, до первой записи — отсутствие наблюдения. Перезапись одинакового OHLCV не должна сдвигать первое время доступности. Историческая выгрузка из ISS получает фактическую дату загрузки и не считается наблюдением в прошлом.
