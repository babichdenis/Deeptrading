# Данные, время и качество

## Источник данных

Исторический потребитель читает PostgreSQL. Загрузка идёт через проверку покрытия и получение недостающего из поддерживаемых источников, а не прямое скачивание внутри стратегии. T-Invest и MOEX — источники со своими семантикой и качеством; сравнение без одинаковых инструмента, интервала, времени и шкалы цены некорректно. `ensure` не означает, что любой пустой ответ доказывает отсутствие торгов.

## Канон времени

- Внутреннее время UTC, timezone-aware; Москва используется на границе UI и явно заданных сессионных правил.
- Метка свечи `T` — **начало** бакета `[T, T+TF)`, границы по UTC-сетке.
- Бар доступен расчёту на `as_of`, когда `T + TF <= as_of`.
- Partial-бар не становится закрытым только из-за наличия строки. Новые агрегаторы с END/ceil-семантикой запрещены.
- Для мер использовать `bar_is_visible` / `bar_close_ts`. Текущую runtime-шкалу `_is_closed` нельзя изолированно заменить: feed и replay clock должны меняться согласованно.

Основание и важное различие шкал расчёта/runtime: [ADR-0002](../adr/0002-timeframe-semantics.md). Эта запись заменяет старую строку MEMORY «метка = закрытие».

## Пропуски и достоверность

Различать отсутствие наблюдения, отсутствие торгов, недоступный источник, повреждённый ответ и невалидные цены. Missing/UNKNOWN не превращать в нулевой результат. Разреженный бакет может закрыться по времени, но это не доказывает пригодность его плотности для конкретного потребителя. Хвостовой finalize и partial-флаги сохраняют смысл; completeness проверяется контрактом потребителя.

Цены, масштаб и corporate actions требуют отдельной проверки. Корректный JSON и монотонные timestamps не доказывают согласованность рядов разных ТФ. Старые гипотезы о сплитах и последние заявления о дефектах не становятся установленными фактами без первичного источника и артефакта сравнения.
