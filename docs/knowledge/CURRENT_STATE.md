## Перенос окружения на Windows .8 — 2026-10-17

Проект продублирован на Windows .8: `X:\Deeptrading` (ветка `second`), Python 3.11.9 в `X:\Deeptrading\backend\.venv`, `node_modules` установлены. `t-tech-investments==1.51.0` перенесён локально собранным wheel, потому что приватный индекс `opensource.tbank.ru` был недоступен и с .7, и с .8. БД перенесена дампом (`pg_dump -Fc --compress=zstd:3`, 3,83 ГБ) и восстановлена в нативную PostgreSQL 16.15 на .8 (`127.0.0.1:5432`, БД `deeptrading`, 46 ГБ, 44 таблицы). Сверка ключевых таблиц совпала точно (signals 371 720, report_trades 54 366, sandbox_trades 4 180, universe 40); свечи разошлись на 102 строки из-за записи на .7 после снятия дампа. Отчёты и артефакты (`backend/reports`) по решению владельца не переносились. Бэкенд на .8 ещё не стартовал: `backend/data/run_state.json` содержит незавершённый `tg_move_v14` и запустит реплей.

## Детерминированный реплей — 2026-10-17

Реплей (`feed=replay`, `pace≠wall`) больше не поднимает фоновые циклы, которые меняют позиции и универс по стенным часам: `held_sync`, `vol_carousel`, `intrabar`, `queue`, `momentum`, `guard`. Остаются `persist`, `hot_add`, `reconcile`, `session`, `metrics`, `imoex` — read-only либо уже с self-guard по реплею. Итог прогона зависит только от свечей БД. Коммит `3750e4d`, ветка `second` (`.8`). В `wall`-темпе циклы сохраняются.

Старт реплея больше не меняет БД из внешнего источника: `_candle_preflight` по умолчанию `warn` (проверка есть, докачки из T-Invest нет; явный env по-прежнему перебивает), `ensure_imoex_candles` в реплее не вызывается, IMOEX-ряд берётся только из БД.

Проверка воспроизводимости: `tg_move_v14` (прежний код, циклы включены) и `tg_g0full` (новый код, циклы выключены) на окне 2025-12-01…2026-10-08 дали одинаковый md5 набора сделок `ea42a7265917a744f9218bb8f0d93e8b` — 801 сделка, net +3 599,74 ₽. То есть на этой конфигурации фоновые циклы не влияли; выключение закрепляет результат. Двойной контрольный прогон той же конфигурации — тест `tg_g0full2`.
