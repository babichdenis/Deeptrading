> Создан 2026-09-15. Не забыть! Гейт уже в бою на .3 (big-pickle + llama3.2:3b параллельно).

## Что уже сделано (2026-09-15)

- AI-гейт входов: worker `backend/scripts/ai_approval_worker.py`, решения approve/reject/skip + **advice**.
- Провайдеры: **opencode/big-pickle** (боевой, применяется) + **ollama/llama3.2:3b** на .2 (параллельно, советник).
- Контекст заявки: now_msk, order, positions, equity, guard, risk, session, recent_trades_ticker,
  **candles_1m (5×1м, МСК)**, **volume (last/mean50/ratio)**, **orderbook (спред/перевес/плотность)**,
  signal_features.
- Гарды: dry-run при confirm=false, live-блок, аудит `ai_approval_log.jsonl`,
  дедуп заявок, **пауза 15 мин после отказа ИИ** (`ai_reject_cooldown_min`).
- UI: 4-я вкладка правого сайдбара «AI-гейт» (решения, советы, 📄 промпт, ⛶ fullscreen).
- Детерминированные правила: loss-streak HOLD (2 убытка → 1ч), тройное подтверждение BUY (3×1м растущих),
  IMOEX guard (+chase/per-ticker beta), held-тикеры не генерируют входы в сторону позиции.
- Замеры: big-pickle ~17–44с, llama3.2:3b ~19–30с (данные игнорирует — шаблонные ответы).
  Быстрые free-модели Zen (mimo/deepseek-v4-flash/nemotron/ling) — 403 Forbidden.

## Этап 1. Статистика гейта (фундамент) — СДЕЛАТЬ ПЕРВЫМ

1. **Персист решений** (сейчас deque в памяти): таблица `ai_decisions`
   (ts, order_id, figi, ticker, side, qty, price, provider, model, decision, reason, advice,
   confidence, latency_ms, agreement, applied, shadow) + индекс по ts/figi.
2. **Трекер исходов** `scripts/ai_gate_tracker.py` (раз в минуту, read-only):
   - для **отклонённых** заявок — контрфакт: цена через +15/+30 мин (и/или симуляция SL/TP по ATR);
     если был бы убыток → «сэкономлено», если прибыль → «упущено»;
   - для **одобренных** — фактический `net_pnl` из `sandbox_trades` (связь по figi+ts);
   - писать в `ai_decision_outcomes` (decision_id, pnl_counterfactual_15m/30m, saved_rub, missed_rub, actual_pnl).
3. **API**: `GET /api/v1/bot/ai_stats?from=&to=` → сводка:
   - заявок/approve/reject/skip, % согласия моделей (🤝/≠);
   - **«Гейт: +X₽ (сэкономлено A, упущено B)»**;
   - точность каждой модели (по факту P&L), топ проблемных тикеров, топ причин отказа;
   - что было бы при политиках `primary | agreement | any_reject`.

## Этап 2. Вкладка «Анализ» (главная страница, левое меню)

Перенести статистику из правого сайдбара (`#sr-pane-stats`) и расширить:

- **Блок AI-гейт**: сводка из `/ai_stats` + таблица решений с исходами (saved/missed).
- **Торговая статистика**: PF/WR/Net по срезам (тикер/режим/сессия/exit_reason/кворум/стратегия),
  средний P&L на сделку, серии, equity/net по дням; фильтр периода; сравнение двух периодов.
- **График эквити** (по закрытым сделкам) + распределение P&L.
- Правый сайдбар: вкладку «Статистика» убрать (оставить Рынок/Голоса/AI-гейт) или оставить
  ссылку «Открыть в Анализе».

## Этап 3. Дайджест (AI-отчёт)

- Раз в день (или кнопкой) big-pickle получает сводку цифр (статистика + решения гейта) и пишет
  10–15 строк: что произошло, что сработало, проблемные тикеры/режимы, что поменять.
- Хранить историю (`ai_digests`: ts, period, text, model) и показывать в «Анализе».

## Этап 4. Quorum-политика

- `ai_gate_policy: primary | agreement | any_reject` (по умолчанию primary).
- `agreement`: применяем, только если обе модели сошлись (иначе — таймаут/default).
- `any_reject`: отклоняем, если хотя бы одна модель против (консервативно).
- Логировать, что было бы при каждой политике → сравнить по saved/missed.

## Этап 5. Роли моделей

- **big-pickle** — решения по входам (сложное рассуждение, данные свечей/стакана).
- **llama3.2:3b (локальная, .2)** — простые задачи: «вахтёр позиций» (раз в 2–5 мин: держать /
  подтянуть стоп к X / закрыть), контроль SL/TP, быстрый фолбэк при недоступности Zen.
  Логировать советы, не применять; сравнить с фактом.

### 5.1 Вахтёр позиций (реализовано 2026-09-15)
- `--watch-positions --providers ollama --watch-interval 60 --ai-sl-manage`
- Фильтр: позиции ближе 1.5 ATR к SL/TP или убыточные.
- Контекст: position (entry/last/pnl/sl/tp/atr/dist_sl_atr/dist_tp_atr/trail), **levels.sl_suggest/tp_suggest**
  (безопасные уровни, чтобы 3B не считала), guard, risk, now_msk.
- **Управление SL/TP разрешено** (только подтяжка, жёсткие лимиты):
  - SL: LONG — выше текущего и ниже цены; SHORT — ниже текущего и выше цены;
  - TP: только ПОДТЯНУТЬ к цене (защита прибыли), не дальше от цены;
  - буфер 0.3 ATR до цены, шаг ≤ 2.0 ATR за раз; при трейлинге уровни не трогаются;
  - всё пишется в `/ai_notes` (`applied_levels`) + событие `SLTP_MANUAL`.
- Если модель сказала «tighten» без числа — берутся `levels.sl_suggest/tp_suggest` (расчёт воркера).

### 5.2 PnL в таблице позиций
- В таблице открытых позиций PnL — **gross** (без комиссий). Рядом мелким шрифтом показывается
  `net ≈` (оценка с комиссией ×2 по `commission_rate`). В закрытых сделках `net_pnl` — уже с комиссиями.

## Этап 6. Саморегуляция (постепенно)

1. Сбор советов по типам (`hold_ticker`, `reduce_size`, `tighten_sl`, `pause_entries`, `check_data`).
2. Типизация: модель возвращает `advice_type` из enum.
3. Полуавтомат: безопасные советы бот исполняет сам (например `hold_ticker` → тот же loss-streak hold).
4. Авто: AI управляет `loss_streak_n/hold_min`, паузами по тикерам, размером позиции — в пределах лимитов риска.
