## 2. МЕХАНИЗМ ПОЛНОГО СБРОСА SANDBOX (реализован; финальный прогон — в пн)

### Почему возникла задача
- Прилагаемый `reset_sandbox_account.py` рассчитывал на Mac/bash: локальный kill uvicorn,
  wipe таблиц — для Windows-бота на `.2` не работал.
- На `.2` бот жил с «мёртвым» `SANDBOX_ACCOUNT=5e4d9c6f…` (вчерашний сброс удалил счёт
  в sandbox, но `.env` на `.2` не обновился — вчера сброс делали на Mac, бот на `.2`
  с отдельной копией). Итог: 50004 NOT_FOUND на каждый GetPortfolio/TradesStream.

### Новый механизм
- **`POST /api/v1/sandbox/reset`** в `backend/app/api/routes/sandbox.py`.
  Пайплайн: остановка бота → закрытие ВСЕХ sandbox-счётов с именем `--name` (дубли и
  «сироты» прошлых сбросов) + закрытие аккаунта из `.env` (NOT_FOUND — ок) → открытие
  нового счёта → **пополнение с ретраями и сверкой по ФАКТИЧЕСКОМУ балансу**
  (`_fund_account`, до 4 попыток, проверка живым `get_sandbox_portfolio`) → при неудаче
  пополнения **откат**: только что созданный счёт закрывается, 502 с человеческим текстом →
  перезапись `SANDBOX_ACCOUNT` в `backend/.env` → `get_settings.cache_clear()` → wipe
  таблиц сделок/истории (`sandbox_trades, paper_trades, paper_positions, paper_accounts,
  ai_decisions` + `bot_logs`) по умолчанию (`keep_history=False`) + архив журналов →
  сброс кэшей портфеля/операций/mаржи + `hub.clear()` → **автостарт бота всегда**
  (через `runtime.config` или `_cfg_from_saved("sandbox")`) → sync `paper_accounts.cash`.
  Ответ: `{ok, account_id, account_name, cash, funded, closed_old, closed_dups, restarted, wiped}`.
- **`backend/scripts/reset_sandbox_account.py`** — переработан в тонкого клиента:
  `--host http://192.168.1.2:8000` (по умолчанию localhost), `--cash`, `--name`,
  `--keep-history`. Без t_tech/БД внутри; читает тело ошибки, таймаут 180с (ретраи
  пополнения идут долго); best-effort синхронизирует локальный `backend/.env`;
  верифицирует `/sandbox/status`, `/bot/status`, `/bot/trades`.
- Обе части задеплоены на `.2`, `py_compile` чист, эндпойнт виден в `/openapi.json`.

### Что проверено рабочим прогоном (до вывода upstream из строя)

## 6. КЛЮЧЕВЫЕ ВЫВОДЫ
- **Правило:** сброс sandbox делать ОДНИМ способом — `scripts/reset_sandbox_account.py`
  против живого бэкенда (локально или `--host`). Не вручную на одной машине — иначе
  второй хост останется с мёртвым аккаунтом (ровно как случилось: Mac сбросил, `.2` нет).
- `get_settings()` — с `@lru_cache`; после смены аккаунта нужен `cache_clear()` ПЕРЕД стартом
  бота. Broker/StreamManager пересоздаются в `runtime.start()`.
- `hub.clear()` чистит только in-memory кольцо — строки `bot_logs` удаляются отдельным DELETE.
- Таймаут запроса ≠ отменён: sandbox может исполнить pay_in позже. Всегда сверять счёта по
  фактическому балансу и делать top-up только по разнице.
- Старый ручной алгоритм (6 шагов из AGENTS) заменяется на одну команду выше.
