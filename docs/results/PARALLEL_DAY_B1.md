## 3. Метод

- **A. Вход**: join features↔targets строго по `row_id` (row_id уникален, targets ⊆ features, `decision_ts`
  всегда на 5m-сетке). Focused-проверки: инверсия `label` в targets не меняет ни один из 58 предикторов.
- **B. Атомы**: 35 continuous TF-признаков × train-квантили `q20/q50/q80` (`<=`/`>`) + 9 `vote_<sid>` (`==+1`/`==-1`).
  Квантили считаются на train (все 5m-решения); uplift = `P(up | atom) − P(up)` на train MATURE.
  Лимиты: support ≥ 1000, train-дат ≥ 30, ≤2 атома на исходный признак, ≤20 атомов; tie-break — canonical atom id.
  Итог: 20 атомов, все лимиты соблюдены (`atom_support_limits`, `atom_source_cap`, `atom_count_cap` = True).
- **C. Правила**: детерминированные одиночки/пары/тройки выбранных атомов, кэпы 20/190/1140,
  пара и тройка обязаны охватывать ≥2 ТФ и разные исходные признаки; две противоположные границы
  одной функции не сочетаются. Сгенерировано 20 + 115 + 1014 = **1149** правил; все train/val
  кандидаты с support/lift/coverage записаны машинно (`rules_all.csv`).
- **D. Отбор по общему п.9**: критерий `val_mean_event_net_c5_s2`, порог известности ≥200 известных
  событий, ≥20 разных val-дат, доля unknown-эндпоинтов ≤5 %. Пороги не понижались. Freeze
  (rules/thresholds/ids/input hashes) записан **до** eval; `no_selection = false`.
- **E. Eval** одним прогоном: тот же daypack, 5 слотов по 20 % капитала, два уровня издержек
  (`c5_s2` = 5/2 б.п., `c10_s5` = 10/5 б.п.), базовые линии `cash`, `always_long`, `best_single_atom`.
- **F. Repro**: один CLI `--dataset --snapshot --out --resume`; после прогона — self-checks
  (нет lookahead/`available_at_ts == decision_ts`, NULL ≠ срабатывание, join по row_id, лимиты,
  неизменяемость выхода, `net == gross − costs_total`).

**Оптимизация (не влияет на результат, только время):** исход сделки (entry = open 1m-бара `decision_ts`,
exit = min(entry+120 мин, 18:44 MSK), cost) не зависит от правила, поэтому исходы считаются **один раз
на решение** для каждого (split, cost); правила агрегируются по битовым маскам атомов
(`true_mask` / `unknown_mask`, UNKNOWN → правило неактивно → покрытие).

## 4. Primary (заморожен до eval)

**`ema50_dist_1m|le|q20`** — одиночный атом, в натуральных единицах:

> `ema50_dist_1m <= -0.00134282` — то есть цена ниже EMA50 (1m) в нижних ~20 % расстояния (train-квантиль 20 %).

- train: support 39 018 событий, 170 дат, `P(up|atom) = 0.4653` против базы `P(up) = 0.4466`, uplift **+0.0186**,
  покрытие определения 38.2 %, покрытие срабатывания 7.6 %.
- top3 (заморожены, не переключались): `ema50_slope_1m|le|q20`, `ema50_dist_600s|le|q20`, `ema50_slope_600s|le|q20`.
- `best_single_atom` = primary (то есть лучшим по критерию п.9 среди всех размеров оказался именно одиночный атом).

### 4.1 Event-level (метрика отбора, не портфельный PnL)

| val | 28 681 | 28 611 | 70 | 0 | 0.00244 | **−0.001574** | 45 |
| eval | 35 462 | 34 842 | 394 | 226 | 0.0111 | **−0.001278** | 49 |

Критерий п.9 выполнен по букве (200/20/5 % с запасом), но его **знак отрицательный**: правило
(и весь его класс) не покрывает издержки на per-event уровне. Это метрика скрининга с пересечением
событий — не портфельный PnL.

### 4.2 Замечание о вырожденности атомов

`ema50_dist_1m|le|q20` и `ema50_slope_1m|le|q20` дают **побитово одинаковые** числа (val/eval event и
портфель), то же — для пары `_600s`. На 5m-решениях `dist` и `slope` одного и того же `ema50`
коллинеарны, поэтому «разные» правила фактически дублируют друг друга; это ограничивает число
действительно независимых гипотез.

Baselines на eval/c5_s2: `cash` = 0.0; `always_long` = −0.210871 (578 closed); `best_single_atom` = −0.094773.

Два важных факта, без которых цифру net читать нельзя:

1. **Издержки съедают весь gross.** Gross primary ≈ −0.011 (то есть до издержек правило почти безубыточно),
   но 0.084 издержек при c5_s2 и 0.169 при c10_s5 дают итог −0.095 / −0.180.
2. **Портфель работает в режиме насыщения ёмкости.** Правило срабатывает на 28 681 val-событии
   и 35 462 eval-событиях, а 5 слотов при удержании 120 мин принимают ~300 сделок:
   `no_slot` 2 415 + `no_cash` 226 + `ignore_repeat` 26 713. То есть портфельный net — это
   выборка ~0.9 % сигналов, ограниченная ёмкостью, а не оценка полного набора сигналов.
   Честная оценка силы правила — event-level `mean_net` из §4.1.

`final_equity = None` — честная неизвестность: на хвосте окна остались открытые позиции
(INCOMPLETE), их выход неизвестен. `known_prefix` пуст (`last_known_equity = 1.0`, `last_known_ts = None`),
потому что первая незакрытая позиция появляется уже в первый день — для правила, живущего почти
непрерывно, «известный префикс» вырождается. Диагностика полного закрытого cash-flow:
`closed_cashflow_diagnostic.closed_net = −0.094773`, `is_full_equity = false`.

## 8. Дефекты, найденные и исправленные до сдачи

1. **`pd.NaT` вместо `None`** при реконструкции исходов из parquet: у SKIP-строк `entry_ts`
   становился `NaT`, объект с `NaT` попадал в «входы» портфеля, `costs.fill` падал
   (`невалидная цена исполнения nan`). На синтетической фикстуре SKIP-строк нет — дефект вылез
   только на реальных данных (eval SKIP = 1 041). Исправлено нормализацией `NaT/NaN → None`;
   добавлен регресс-тест `test_skip_row_nat_is_not_an_entry`.
2. **`ticker_month.csv` смешивал две группировки** (тикеры и месяцы в одной таблице, из-за чего
   `ticker` был пуст в строках месяцев). Исправлено: явные колонки `kind` (`ticker`/`month`),
   `cost` и второй уровень издержек. Тесты: `backend/tests/test_research_day_b1.py` — 16 passed.

## 9. Ограничения

- `corporate_actions_unverified` — корпоративные действия/сплиты снапшота не верифицированы.
- `snapshot_coverage_uneven` — неполное m1-покрытие ⇒ INCOMPLETE/SKIP, а `unknown ≠ 0`; хвост окна
  остаётся с открытыми позициями, поэтому `final_equity` не определён.
- `eval_period_is_part_of_development_history` — окно eval уже было в истории разработки, это не
  независимый holdout.
- `development_unvalidated` — результат не является доказательством прибыльности; метрика отбора —
  скрининг с пересечением событий, а не портфельный PnL.
- Ёмкость: 5 слотов × 120 мин удержания делает портфельную оценку выборкой ~0.9 % сигналов.
- Коллинеарность `ema50_dist_*` и `ema50_slope_*` на 5m-сетке сокращает число независимых гипотез.
