## Что предлагается — три независимые, opt-in части

### A. Точная минута исполнения — `Signal.execute_at`
- API: `app/engine/models.py:59-66` → `execute_at: datetime | None = None` (append).
- Runner: `runner.py:226-277` (блок исполнения pending) — при `execute_at is None`
  поведение прежнее; `< bar.ts` → pending сохраняется; `> bar.ts` → pending
  отменяется. Entry: только audit. Exit/flip: при `emit_unresolved` → unknown (B).
- Ledger: audit `REJECT_EXECUTION_BAR_MISMATCH`; `Trade` не создаётся.
- Потребители: `strategy_state.py:57-59` читает лишь `time/side/reason/features`.

### B. Unknown outcome вместо выдуманного PnL
- API: `ExitReason.UNDETERMINED` (`models.py:29-46`); `UnresolvedPosition`
  (`models.py`, новый dataclass); `EngineConfig.emit_unresolved=False`
  (`runner.py:23-76`).
- Runner: конец данных `runner.py:625-628` — при `emit_unresolved and force_unresolved`
  вызывается `_emit_unresolved` (`UnresolvedPosition`), иначе прежний `END_OF_DATA`.
  Позиция не «исчезает»: неизвестный исход сохранён явно, PnL не выдуман.
- Ledger: `unresolved: list` + `add_unresolved` (`ledger.py:9-31`); `fingerprint`
  добавляет блок `UNRESOLVED` **только при непустом списке** → fingerprint прогонов
  без unknown-исходов не меняется.
- Потребители: `experiments.py:356-374` (отдельная таблица), `ensemble.py:1551-1818`
  (unknown не в PnL, считается отдельно); ORM-таблицы закрытых сделок не трогаются.

### C. Политика TP-gap (opt-in)
- API: `ExitPlan.tp_gap_at_level` (`models.py:69-72`), `Position.tp_gap_at_level`
  (`models.py:75-88`).
- Runner/exits: `intrabar_exit(..., tp_gap_at_level=False)` (`exits.py:305-312`) — при
  гэпе через TP возвращает raw TP вместо `bar.open` (`exits.py:351-353` LONG,
  `:375-377` SHORT); `runner.py:293-296` передаёт флаг, `runner.py:709` переносит из
  плана, `_close` применяет slippage к raw TP → A7-семантика `fill(tp_level)`.
- Ledger: `exit_reason` остаётся `target`; audit `TP_GAP_AT_LEVEL`.
