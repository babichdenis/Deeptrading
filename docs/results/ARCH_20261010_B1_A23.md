## 1. Этап 1 — `request_plan.json` (план ограниченного read-only сбора)

Из принятого A19 (`recovery_request.json`, sha в манифесте) — **ровно 89 уникальных минут**
(`expected_89=true`), по тикерам: **SFIN 65, VKCO 17, LKOH 4, SBER 3**; FIGI из A10 raw
(`VKCO=TCS00A106YF0` и т.д.).

**Правило окон:** ±5min вокруг целевой минуты, UTC half-open `[target−5min, target+6min)`;
слияние пересекающихся/смежных окон **внутри ticker/day**, без расширения до истории. Фактически
**слияние не потребовалось** — при группировке по ticker+day близких (<11 мин) пар нет → **89 окон
= 89 targets, без дублей**.

**Бюджет вызовов (bounded):**
- **ISS: 64 вызова** — по distinct `(ticker, day)`, т.к. `from=till=day` возвращает весь день
  (лимит `ISS_MAX_PAGES=10`, timeout 20 с, retries 2 → worst-case 38400 с);
- **T-Invest: 89 вызовов** — один `GetCandles (figi, from, to, 1min)` на окно (timeout 20 с,
  attempts 2 → worst-case 5340 с);
- **total max wall time = 43740 с (≈729 мин)** — это жёсткая верхняя граница, не ожидаемое время.

**Пилот (только три VKCO даты из A19 deep-dive):** 4 окна по дням 2026-07-10 / 2026-08-05 (2 окна)
/ 2026-08-06; **ISS 3 вызова, T-Invest 4**.

**argv / недостающее соответствие CLI:** offline-argv для каждого окна собран массивом
(`--mode offline --input <raw_dir> --out <out>`), но **выполняется только когда raw уже сохранён**.
Для collect — A5 **захардкожен константами модуля** (`FIGI/TICKER/BOARD/ISS_DAY/WINDOW_START/
WINDOW_END/INTERVAL`, строки 42–51) и **не принимает их через CLI**; поэтому на каждое окно
зафиксировано **точное недостающее соответствие CLI** (какие константы и на что параметризовать).
Период `collect` в A23 **не выполняется** — план готов к отдельному разрешению на ограниченный
read-only сбор; **авторизации на сеть пока нет**.

**Сравнимость:** T-Invest и MOEX ISS сопоставляются **только для того же инструмента/рынка/
интервала/сессии**; если ISS не даёт сопоставимых 1m — `NOT_COMPARABLE` (не превращать 10m в
вымышленные минуты).

## 2. Этап 2 — offline intake (`consume`)

Отдельный режим `consume` в том же скрипте: читает явно сохранённые responses + `manifest.json`
(sha256 каждого файла), сверяет с планом, выдаёт `comparison.jsonl` со статусами
`exists / absent / unavailable / not_comparable / invalid_input` + provenance (источник, окно,
fetch_status, pagination, interval, declared/computed sha, hash_match).

- **Нормализацию цен/времени переиспользует из A5** (`norm_iss_rows` / `norm_tinvest_rows`),
  не дублирует. Индекс по ts строится в A23, т.к. `A5.index_by_ts` фильтрует по захаркоженному окну
  SBER (`WINDOW_START/END`) и неприменим к arbitrary-окнам (это не нормализация, а фильтр окна).
- **Свеча отсутствует → `SOURCE_ABSENT`, причина UNKNOWN** (не «источник не торговал»/«экспорт
  потерял» — причинные ярлыки не придумываются, по умолчанию SOURCE_ABSENT/LOCAL_ABSENT/UNKNOWN).
- **Повреждение / неполная пагинация / ошибка ответа ≠ пустые данные**: `invalid_input` /
  `unavailable`, а не `absent`.
- Никаких исправлений CSV/DB и пересчёта стратегий.
