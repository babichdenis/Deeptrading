## API и контракт приёмки сигнала

```python
execute_candidate_signal(signal, tdata, costs, *, expected_spec_hash=CANDIDATE_SPEC_HASH) -> dict
```

- Принимает ПРИНЯТЫЙ A18 `signal` event; **сигнал не генерируется повторно** и не
  меняется по будущему пути.
- Проверки (несовпадение => явный `REJECT` без мутации): `type==signal`;
  все обязательные поля; `candidate_id in (C1,C2)`; `ticker` совпадает с
  `tdata.ticker`; `spec_hash` == канон A17; `side in (long,short)`;
  `atr` конечный и > 0; `decision_close_time == intended_entry_time`;
  `observed_until >= decision_close_time`; минута входа выровнена;
  `msk день входа == signal.day`.
- Вход: **open РОВНО `intended_entry_time`**; минуты нет => `SKIP missing_entry`
  без переноса/повторного входа (следующая минута вход не заменяет).
- SL = raw entry − side·2·ATR, TP = raw entry + side·3·ATR для ОБОИХ C1/C2
  (ATR — из принятого сигнала, не пересчитывается; множители A7).

## Путь и accounting — ТОЛЬКО существующий A7

- Путь: `day_strategies_core._walk` без изменений — gap SL по факт. adverse open,
  gap TP по raw уровню (улучшение не берём), intrabar SL раньше TP,
  time-exit 18:30 при полном 18:20, непрерывность обязательна.
- `_walk is None` => политика incomplete A7 (не закрывать последним close):
  `time_exit_bar_18_20_incomplete` / `time_exit_minute_18_30_missing` /
  `data_ended_open_position`.
- Accounting: `CostParams.validate/fill/commission`; формулы A7:
  `entry_fill=fill(entry_base,side)`, `exit_fill=fill(exit_base,-side)`,
  `gross=side*(exit_base-entry_base)`, `fill_delta=side*(exit_fill-entry_fill)`,
  `net=fill_delta-ce-cx`, `costs_total=ce+cx+(gross-fill_delta)` — тождество
  `net=gross-costs_total` по построению (проверено численно в E15).

## Ledger-семантика (A7-совместимая)

`FILLED` (все fills/fees/net), `INCOMPLETE` (вход+fills входа сохранены, exit/net
неизвестны), `SKIP missing_entry`, `REJECT <code>`. Запись несёт signal identity +
`signal_hash` (sha256 канонического JSON события), raw entry/exit, fills/fees,
reason/timestamps. Одна позиция на candidate/ticker/day (по построению — ровно
один signal на день). C1/C2 — независимые research-ветки, не портфель;
идентификаторы не подменяются на S1/S2.
