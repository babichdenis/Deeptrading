## 3. Происхождение и граница неизвестного

**Доказано:** бар `2026-09-08 12:47:00+00:00` figi SBER `BBG004730N88`
interval=1, O=H=L=C=1.0, volume=0 физически есть в `candles`, единственный для
FIGI; соседние валидные бары 12:46 (280.01/280.04) и 12:51 (280.09/280.22);
день имеет корректную интервальную структуру; если известен причинный
предыдущий close (~280) и рассчитанный jump>0.40 (для 280→1.0 ≈0.996),
live-стрим и backtest-гейт отклонили бы такую свечу; при prev_close=1.0
(плюсовом, но аномальном) jump=0 и отбрасывания нет; историческое состояние
prev_close на момент записи неизвестно; Lab передаёт его в стратегию как
обычную свечу. Минимальный след
(по A1): затронутая ячейка SBER — `williams_range_hub / 1min / SBER / BUY / NEUTRAL / day`
(PF_norm 204.27; PF_rub 0.7367, trades 266) — см. A1.

**Не воспроизведён:** в текущем коде проекта генератор 1.0/vol0 не
обнаружен — «дефект кода не воспроизведён» при проверке текущей ревизии
(не доказывает отсутствия исторического дефекта; см. H7).

**Не установлено (NOT_VERIFIED):** какой внешний банк (T-Invest / MOEX ISS /
CSV-экспорт) отдал 1.0-бар и какой из безгейтовых писателей его записал —
это гипотеза, не установленное происхождение. Причина — данных-следа нет:
никаких `source`/`created_at`; в проверенной выборке integrity по дню строк
нет (история построения неизвестна). Это честная граница, не «недосмотр».

## 4. Одно приоритетное следующее действие (с критериями)

**Действие: проверка оригинальной свечи.** Сохранить отдельный raw-ответ от
внешнего источника (T-Invest 1m или ISS 1m) за `2026-09-08 12:47Z`
(15:47 МСК), без автоматического upsert/удаления/замены `candle_integrity`
baseline в рамках этой задачи. Сравнение сырого ответа с имеющейся строкой,
фиксация результата (raw + сравнение + вывод). Доступ к внешнему API и
изменение данных в A3 не назначаются.

Критерии проверки:
1. Raw-ответ за 12:47 сохранён отдельно (файл/тело ответа), исходная строка
   `candles` не изменялась.
2. Сравнение raw ↔ строка БД зафиксировано (совпало / расходится — со значением).
3. Фиксируется нынешний ответ поставщика и совпадение/расхождение со строкой
   БД за 12:47. Это фиксирует только текущее состояние источника: новый ответ
   сегодня НЕ подтверждает и НЕ снимает происхождение исторической записи
   (историческая версия могла измениться; писатель остаётся неизвестен).
   Результат соотносится с H1/H4 как данные, а не как вердикт.
4. Никакой автоматический upsert/удаление/перезапись baseline не выполняется.

Реализация write-side гейта отложена в §5 (P0-кандидат, требует отдельного
рассмотрения: нет гарантии обнаружения скачка при отсутствии prev_close,
возможны изменения масштаба цены; порог 0.40 НЕ подстраивать под PnL,
существующие данные НЕ править задним числом).

  таблицу/лог, строка НЕ удаляется. Первый бар без prev → только `bar_ok`.
  Критерии: синтетический `{OHLC=1.0, vol=0}` отклоняется; валидный ряд пишется
  без изменений; первый бар без prev проходит; хэши существующих строк не
  меняются; hermetic pytest 0 failed. Требует отдельного рассмотрения (см. §4).
- P1: колонки `source VARCHAR` + `created_at` в `candles`; заполнять в W1-W5;
  миграция как deployment-gate (закрывает и пункт миграций аудита 07.10).
- P2: узкая data-quality preflight перед загрузкой периода в Lab: счёт
  placeholder-подобных баров (`o==h==l==c AND vol==0`) и прыжков>40% с
  отчётом причин; период с подозрительными барами требует подтверждения
  человека до прогона. Без подбора порога по прибыльности.

## 6. Соседние проблемы (вне контракта, не исправлялись — передаются)

1. `app/bot/moex.py:61-62` `moex_candles`: `ts` интерпретируется как UTC без
   сдвига из МСК (`fromisoformat(...).replace(tzinfo=timezone.utc)`), тогда как
   `data_backfill._moex_candles:67` и `imoex_candles:100` конвертируют из МСК
   корректно → для путей W3 ts может быть смещён на +3ч. Касается времени,
   НЕ цен; на аномалию 1.0 не влияет.
2. Читатель Lab (R1) не применяет `candle_guard.validate_candles` — единый
   движок «тест=бот» (договорённость) на стороне Lab не выдержан.
3. `candle_integrity`: в сохранённой выборке по SBER за интересующие сутки
   строк нет; история построения неизвестна — нельзя автоматически доказать,
   что день «чистый».
