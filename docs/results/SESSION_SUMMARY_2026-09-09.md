# SESSION_SUMMARY_2026-09-09 — «Карусель» SBER: стрим→polling-перемотка баклога
> **Актуальная сессия:** `docs/results/SESSION_SUMMARY_2026-09-15.md` (портфельный риск, очередь, ранжирование).


> **Дата:** 2026-09-09. Пользователь: SBER/NVTK/ROSN чирикают —
> вход SBER → закрытие через ~60с, сигналы BUY/SELL флипают каждые 2-3 сек.
> Причина найдена и ПОЧИНЕНА: после рестартов feed падал в polling-режим, который
> **с ускорением ~60× перематывал исторический баклог** старой сессии, и стратегия
> торговала каждую старую свечу. Лечение: гейт «только закрытая свеча» + гейт
> «свежести по wall-clock» в runtime + таймаут первой свечи стрима 15с→75с.

- Свечи шли с **шагом ts 5-10 минут** при wall-clock 3-15 сек между ними =

  основная масса пришедших свечей = старый баклог.
- Probe-скрипт (`probe_tmp.py`, удалить после расследования) показал:
  `get_candles` в polling для 1min возвращает стабильные закрытые свечи —
  НО в sandbox/после долгого простоя отдаёт свечи старого утра.

## 3. КОРЕНЬ ПРИЧИНЫ

- Бот должен жить на **живом gRPC-стриме** (`waiting_close()` подписка) —
  тогда свечи приходят по одной и только что закрытые, никакого баклога.
- `feed.stream()` падает в polling, если **первая свеча не пришла за 15 сек**
  (`first_candle_timeout = 15.0`). Но `waiting_close()` отдаёт бар ТОЛЬКО в
  момент закрытия минутного интервала → при старте в середине минуты первый
  бар приходит через 30-60с → СТРИМ ВСЕГДА умирал за 15с → polling →
  перемотка утренней истории → «карусель».
- Т.е. **«карусель» появлялась именно после РЕСТАРТА бота** (перезапускали
  uvicorn многократно, каждый раз бот заново входил в свой «авральный» цикл).

## 4. ФИКСЫ (все в `backend/app/bot/runtime.py` и `backend/app/bot/feed.py`)

### 4.1 `runtime.py` — гейт «только ЗАКРЫТАЯ свеча»
Новый метод `_is_closed(c)` (~строки 213-242, рядом с `_candle_ok`):
```python
def _is_closed(self, c) -> bool:
    step = STEP_SEC.get(self.config.interval_name, 60)
    if (datetime.now(timezone.utc) - c.ts).total_seconds() < step:
        return False   # формирующаяся (незакрытая) → не допускать
    return True
```
Применение в `_process_candle` (~1135-1141): после `_candle_ok`, ДО persist —
незакрытая свеча → `DATA_UNCLOSED_CANDLE` + return (не пишем в БД, не кормим стратегию).

### 4.2 `runtime.py` — ГЕЙТ СВЕЖЕСТИ (wall-clock) ~строки 1166-1180
После TECHINFO, ПЕРЕД допуском к стратегии/`_execute_pending`:
```python
_step = STEP_SEC.get(self.config.interval_name, 60)
_age = (datetime.now(timezone.utc) - c.ts).total_seconds()
if _age > _step * 2:
    self._candles_rejected += 1
    self.events.log("DATA_STALE_CANDLE", figi=figi,
                    reason=f"stale age={int(_age)}s ts={c.ts}")
    return
```
**Важно:** расположение — после persist-пуша, Т.е. старый баклог всё равно
пишется в БД (закрытые данные не теряем), но НЕ торгуется.

### 4.3 `feed.py` — таймаут первой свечи 15с → 75с (~строки 108-115)
```python
# waiting_close() отдаёт бар ТОЛЬКО при закрытии минутной свечи — при старте
# в середине минуты первый бар придёт через 30-60с. Таймаут 75с (больше
# максимального ожидания закрытия) держит живой стрим и не даёт упасть в
# polling с перемоткой исторического баклога.
first_candle_timeout = 75.0
```
