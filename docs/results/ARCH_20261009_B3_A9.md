## 2. Классификация и машинно-читаемые данные (r2)

Правило допуска: время/side/статус — точное; цены/деньги — `isclose(rel=abs=1e-9)`;
причина выхода сравнивается по **категории** (`stop`/`tp`/`time`/`session`/`end_of_data`),
исходные строки причин сохранены в `field_diff.csv`. Никаких «залечиваний» округлением,
удалением сделок, искусственной свечой или знанием будущего.

**Сравниваются только поля, реально доступные у обеих сторон.** Поля, которых API
движка не даёт (сырые `entry_base`/`exit_base`/`gross_base` — `Trade` отдаёт только
исполненные цены), помечены `available=False`/`NOT_AVAILABLE`, а не подменены расчётом
от эталона и не выдаются за совпадение.

Классификация дня:

- **MATCH** — A7 skip И движок без сделки; либо FILLED и все доступные поля совпали;
  либо никаких различий по доступным полям нет.
- **EXPECTED_DIFFERENCE** — только заранее описанная разница при совпавшем известном
  префиксе:
  (a) A7 INCOMPLETE (путь неизвестен) против числового закрытия движка
  (стоп/цель/end_of_data) — при **полном совпадении** известного входа
  (side/signal_time/entry_time/entry_fill/sl/tp);
  (b) **доказанный TP-gap**: A7 закрыл по уровню (`exit_fill == tp_level`,
  reason `tp_gap_open`), движок — по open за уровнем, и все различия только в
  `exit_fill`/`gross_fill_delta`/`net` (+ при издержках `commission`/`slippage`).
- **BLOCKED** — отсутствующий/лишний/неверный вход; поздний выход на недопустимом
  баре; любое необъяснённое числовое расхождение. Всегда с полями.

**TP-исключение теперь доказывается числами, а не названиями полей** (item r2).
EXPECTED_DIFFERENCE для FILLED ставится, только если `_tp_gap_proof` подтвердит всё:
1. `ref.exit_reason == "tp_gap_open"`, `engine.exit_reason == target`;
2. в **engine input** есть свеча с `ts == engine.exit_time`, и её `open` строго за raw TP
   по направлению улучшения (LONG `open > tp`, SHORT `open < tp`);
3. raw TP отдельно от slipped fill: `ref.exit_fill == costs.fill(tp_level, exit_side)` и
   `ref.slip_exit == ref.exit_fill − tp_level` (поэтому при 5/2 bps `ref.exit_fill ≠ tp` —
   старый критерий `exit_fill == tp_level` был неверен);
4. engine: `engine.exit_price == costs.fill(candle.open, exit_side)`;
5. по каждому различию фактическая дельта `engine − ref` совпадает с ожидаемой из
   CostModel/qty=1: `exit_fill`, `gross_fill_delta`, `commission`, `slippage`, `net`.
Различие в неразрешённом поле, отсутствие свечи выхода или несовпадение любой дельты →
**BLOCKED** («TP-gap не доказан численно»). Базовая цена движка НЕ берётся из эталона:
raw base выхода = `open` свечи. Необъяснённое изменение net при настоящем гэпе — всегда BLOCKED.

В наборе EX04 доказывается численно: свеча выхода `open=96.5` (SHORT, строго за TP=97.0),
A7 `fill(TP)=97.0`, движок `fill(open)=96.5`, дельты согласованы. Ручной набор
`tpgap_selftest.json` (3/3 passed) проверяет zero-cost gap, gap при 5/2 bps и **тот же
gap с испорченным net** — последний даёт BLOCKED (фактическая дельта net −1000 ≠
ожидаемой +0.5).

## 3. Расхождения (честно, с минимальным воспроизведением)

### 3.1 BLOCKED — 2 кейса, один корень: движок не сверяет бар исполнения

Движок исполняет `pending` на **следующем** баре без проверки ожидаемого `ts`
(`runner.py:226-228`). Причинно проверить, что следующая минута ровно та, нельзя.

| Пример | A7 | Движок (факт, `engine_trades.csv`) | Почему блокер |
|---|---|---|---|
| EX09b `entry_minute_missing` | skip (`entry_minute_missing`) | LONG @ `09:11Z` (12:11 MSK), выход `end_of_data` | 12:10 отсутствует; движок вошёл на 12:11 — вход на недопустимом баре |
| EX12b `time_exit_minute_18_30_missing` | INCOMPLETE | `signal_exit` @ `15:31Z` (18:31 MSK) | 18:30 отсутствует; движок закрыл на 18:31 — выход на недопустимом баре |

**Минимальное предложение по API** (без ломки общего движка): добавить в
`app/engine/models.py::Signal` необязательное поле ожидаемого времени исполнения,
напр. `execute_at: datetime | None = None`, и в `runner.py` при обработке `pending`
отбрасывать его, если `bar.ts != signal.execute_at` (лог
`REJECT_EXECUTION_BAR_MISMATCH`). Это делает `exact next_open` A7 выразимым.

**Важно (item 4):** поле `execute_at` само по себе полную parity НЕ закрывает.
Отбрасывание запоздалого exit оставляет позицию открытой на конец данных; чтобы
сравниться с A7, нужны отдельные решения ещё по двум конвенциям: (1) статус
**INCOMPLETE** для незакрытой позиции и (2) TP-gap (A7 — уровень TP, движок — open).
Поэтому EX09b/EX12b остаются **допустимыми BLOCKED** и не повод менять общий движок
без отдельного назначения. Пока поля нет — адаптер честно метит эти дни BLOCKED.

### 3.2 EXPECTED_DIFFERENCE — 7 кейсов, два определения

|---|---|---|---|

## 5. Выводы для решения

**Что работает:** адаптер S1/S2 живёт в существующих точках расширения движка
(`Strategy`/`ExitPolicy`), причинный, детерминированный; на 30 синтетических примерах
даёт 21 сделок, совпадающих по **доступным** полям (raw base у движка `NOT_AVAILABLE`,
поэтому полная field-parity не подтверждена), а расхождения — воспроизводимо объяснимые
(8 определений, 2 блокера с одним корнем).

**Что блокирует полную parity:** единственный корень — движок исполняет pending на
