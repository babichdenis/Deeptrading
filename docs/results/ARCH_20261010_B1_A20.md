# A20 — Фиксированный протокол следующего независимого наблюдения

**Builder-1 · 2026-10-10 · REVIEW.** Задание из очереди Q2. Зона:
`docs/results/ARCH_20261010_B1_A20.md` + `backend/reports/architect_20261010/b1/a20/20261010T211827Z/`.

**Статус:** документ + `protocol.json`, **без запуска**. Это фиксация того, КАК будет измерено одно
будущее наблюдение; прибыльность не доказывается, реальные тарифы/капитал/live не назначаются.

## 1. Исходное положение (честно)

- **A10 уже просмотрен и НЕ holdout.** Все данные до 2026-10-08 — development-материал. Любой
  «нетронутый» период начинается только после явной фиксации версии кода/данных (§2).
- **VKCO S1-A short — одна post-hoc гипотеза** (из A14/A12: closed_subset +31.65 / +24.25 при двух
  издержках, 32 closed + 3 INCOMPLETE). Два cost-сценария = **одна** гипотеза, не две.
- **C1/C2 — отдельно разработанные кандидаты** (A17 canonical, A18 генератор), **без market
  acceptance**; VWAP — typical-price proxy, не trade-level.

## 2. Фиксация версии — обязательна до наблюдения

Нетронутый период начинается **строго после** публикации в chat хэшей: `day_strategies_replay.py`,
`day_strategies_core.py`, `day_research_report.py` (принятый A11 r3), `day_candidate_signals.py`
(для C1/C2) и самого `protocol.json`. После фиксации — **никаких тихих изменений**; любой дозапуск
«до красивого результата» запрещён. Обнаружение version drift → стоп, новая фиксация как новый
протокол, старый результат `invalidated_by_version_drift`.

## 3. Окно наблюдения — практический минимум, не гарантия мощности

- **start**: первая торговая сессия строго **после** даты фиксации версии.
- **длительность**: **4 календарных месяца** (≈84 торговых дня, по аналогии с A12).
- **обоснование (практический минимум):** на A12 (окно ~4 мес, 84 дня) медианный темп ≈ **2.6
  закрытых сделки на ячейку** ticker×config×side в месяц; 4 мес ≈ **10 закрытых на ячейку**
  (медиана 13, min 3, max 44 из 40 ячеек). Это наименьшее окно, дающее порядка 10 наблюдений на
  «среднюю» ячейку. **Редкие ячейки** (SFIN, S2, min 0.6/мес) останутся неполными — фиксируется
  заранее и **не интерпретируется**. Это **не** гарантия мощности и **не** доходность.
- **гранулярность:** месяцы (`month_msk`) и дни (`day`) отдельными строками. Продление окна — только
  явной новой фиксацией, не тихо.

## 4. Два cost-сценария — отдельно, одна гипотеза

`costs_5_2bps` (5/2) и `costs_10_5bps` (10/5) считаются и отчётятся **раздельно**; это **одна**
гипотеза/кандидат при двух издержках. Сделки/сигналы идентичны (издержки меняют только net).
Оба сценария **условные**; реальные тарифы **не назначаются**.

## 5. Контракт отчётности

- **closed (FILLED) и unknown (INCOMPLETE) — отдельно**; INCOMPLETE **не** считается сделкой и **не**
  скрывается за UNKNOWN-итогом.
- По ячейке ticker × config × side × scenario, по месяцам и дням: `n_closed, n_incomplete,
  n_skipped, net, gross, costs, sum_R` (на 1 акцию, не портфель; тикеры не складываются).
- SBER — `KNOWN_BAD_INPUT/economics_not_eligible`; `source_truth=NOT_VERIFIED`; прибыльность
  `UNKNOWN/descriptive_only`; надписей OOS/WF/PASS нет.

## 6. Правила остановки — только по качеству, не по результату

- Стоп/флаг при: превышении доли INCOMPLETE выше зафиксированного порога (флаг `underpowered`,
  не пересчёт); обнаружении version drift; SBER остаётся исключённым из экономики.
- **НЕ разрешается** останавливать/продлевать из-за «плохого»/«хорошего» net.
- `MIN_CLOSED=10` на ячейку — дескриптивный порог «достаточно для чтения»; ячейки ниже —
  `underpowered`, выводы не делаются.

## 7. Неизвестные исходы (missing outcomes)

Для каждого INCOMPLETE полный эффект **UNKNOWN**, без интерполяции. Допустимо честно показать
границы `[вход − costs, +∞)`, но это **не** оценка эффекта. При наличии `recovery_request` (A19) —
сверить у T-Invest/ISS **до** интерпретации (`EXISTS`/`NOT_TRADED`/`LOST`/`UNKNOWN`).

## 9. Необходимые входы/доступы

**Offline сейчас:** зафиксировать хэши кода/данных; dry-run раннера на сохранённых данных как
валидацию (не как наблюдение); спека `recovery_request` (A19) готова, сеть не вызывалась.

**Для будущего запуска:** доступ к T-Invest за минутными свечами наблюдаемого окна (network, свежие
данные после фиксации); хранилище PostgreSQL через `ensure_candles` (докачка только недостающего);
зафиксированные хэши кода.

**Запрещено:** новые реальные тарифы; назначение капитала/размера позиции; live/ордера/деплой; тихое
изменение версии или дозапуск до красивого результата.

## 10. Воспроизводимость — достаточно для одного запуска

Этот документ + зафиксированные хэши достаточны для **одного** будущего запуска: выбрать
start-правило → скачать свечи окна → прогнать зафиксированную версию по 2 сценариям → отчётить
closed/unknown по месяцам/дням. Повторный прогон той же версии обязан давать тот же
fingerprint(ledger); расхождение = invalidate. Это **один** фиксированный протокол, не roadmap;
изменённая версия = новый `protocol.json`, не правка этого.

## 11. Ограничения

тарифы/капитал/live не назначаются. `phase=development_unvalidated`, `holdout=NOT_ASSIGNED`.
Хэш `protocol.json` — в `manifest.json`.
