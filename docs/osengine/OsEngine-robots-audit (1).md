# Аудит роботов OsEngine по методу действия

Клон `master`, HEAD `34daed3`. Инвентаризация автоматическая: 164 класса с атрибутом `[Bot(...)]` в `project/OsEngine/Robots/`, суммарно **80 410 строк**, медиана **353 строки** на робота, диапазон 36–3231.

Полная машина-читаемая выгрузка с описаниями и индикаторами — в `robots-inventory.tsv` (7 колонок: каталог, имя бота, LOC, типы табов, файл, источник описания, индикаторы, описание).

Группировка ниже — **по методу действия**, а не по каталогам: каталог в проекте часто отражает происхождение (уроки, сэмплы, «стартовый набор»), а не торговую механику.

## 0. На чём всё держится: общий каркас

Каждый робот — класс `: BotPanel`. Три обязательных элемента:

```csharp
TabCreate(BotTabType.Simple);            // источник данных
_tab = TabsSimple[0];
_tab.CandleFinishedEvent += _tab_CandleFinishedEvent;   // точка входа в логику
```

**Источники данных (табы)** — распределение по 164 роботам:

## E. Детекторы рыночных событий и импульса (4 робота, 2 677 строк)

**Механика.** Не «индикатор дал сигнал», а «на рынке произошло событие»: резкий рост цены, рост волатильности, перекос стакана.

| Робот | Строк | Что детектирует |
|---|---|---|
| `PumpDetectorScreener` | 308 | изменение цены выше порога `MoveToEntry` |
| `PlateDetectorScreener` | 330 | перекос стакана: отношение лучшего бида ко всем выше порога |
| `SpeculantSetAtrKeltner` | 1029 | ATR (тип Percent) вырос на заданную величину + Keltner + Bollinger-фильтр |
| `SpeculantSetMomentumAdaPc` | 1010 | Momentum выше минимума + позиция в адаптивном канале + Envelop-фильтр |

`SpeculantSet*` — самый проработанный представитель группы. Конструкция: **два независимых скринера** — один для лонгов, один для шортов, с раздельными параметрами под раздельную оптимизацию. У `SpeculantSetAtrKeltner` есть фильтр `_shortBlockDuringDividends` (по умолчанию `true`) — шорт блокируется в период дивидендов, данные тянутся через `WikiMaster`.

**Где применять.** Крипта и акции второго эшелона, где случаются импульсы. Выход по стопу и профиту, не трейлингом — импульс либо сразу даёт движение, либо нет.
**Осторожно.** Детекторы ловят и насосы, и дампы. `PumpDetectorScreener` входит **по факту** движения, то есть заведомо по худшей цене; прибыль возможна только если движение продолжается.

| `GridTwoSides` | 255 | P | ATR упал в M раз относительно N свечей назад → сетки в обе стороны |
| `GridTwoSignals` | 342 | P | пробой нисходящего PriceChannel, затем долив при возврате к центру |

## I. Арбитраж синтетических облигаций (4 робота, 11 567 строк)

Самая сложная группа в проекте — до 3231 строки на робота.

**Механика.** Синтетическая облигация в контанго: **лонг акция (база) + шорт фьючерс**, дельта-нейтрально. Объёмы в лотах: `база = контракты фьючерса × мульт / лот акции`. Свободные деньги паркуются в LQDT.

| Робот | Строк | Что делает |
|---|---|---|
| `SyntheticBondsArbitrage` | 3231 | 10 пар источников (`BotTabSimple` база + `BotTabScreener` фьючерсы), классический контанго-арбитраж |
| `SyntheticBondsCurveArbitrage` | 3136 | то же + работа с кривой доходности серий |
| `SyntheticBondsScalper` | 3213 | круглосуточно (день/ночь/выходные), вход **только лимитными ордерами по стакану** |
| `SyntheticBondsCurveMonitor` | 1987 | **не торгует**: таблица трёх ближайших серий по каждой бумаге с доходностью в % годовых, алерты по закрытию свечи |

Расчёт: `CalculateContango` возвращает `(deviation, yieldAnn)`, где `deviation = fut.Bid/mult − base.Ask` в процентах, `yieldAnn = deviation × 365 / daysToExpiration`. Возвращает `(0,0)`, если свечи не синхронизированы, нет контанго, невалидные bid/ask или истёк срок.

**Где применять.** MOEX, фьючерсы на акции, где устойчиво держится контанго. Горизонт — до экспирации.
**Осторожно.** Требует точного учёта лотов и мультипликаторов; ошибка в `мульт` ломает дельта-нейтральность. В тестере лот принимается равным 1, то есть **тестер не воспроизводит реальную размерность** — это прямое расхождение бэктеста и боя.

## Наблюдения по качеству

**1. Реальная торговая логика тонкая, обвязка толстая.** Медиана 353 строки, при этом типовой трендовый робот (`PriceChannelTrade`, 353 строки) содержит ~30 строк условия входа. Остальное — параметры, сериализация настроек, GUI, логи. Это нормальная пропорция для платформы с визуальным конструктором, но означает: **читать надо не код стратегии, а то, что вокруг**.

**2. 74 робота из 164 не используют индикаторы вообще.** Вся арифметика по свечам делается вручную. Плюс — нет зависимости от перерисовки индикаторов. Минус — одна и та же логика «три растущие свечи» переписана в `ThreeSoldier`, `ThreeSoldierVolatilityAdaptive`, `ThreeSoldierAdaptiveScreener`, `AlgoStart2Soldiers`, `GridScreenerAdaptiveSoldiers` пять раз, с расхождениями в деталях.

**3. Скринер — основная «взрослая» конструкция.** 47 роботов используют `BotTabScreener`. Именно там сосредоточены самые проработанные системы (сектора, синтетические облигации, грид-скринеры). При этом в модуле скринера найдены два бага, описанных в `OsEngine-screener-module.md`: двойная подписка `tab.MyTradeEvent +=` (строки 3084 и 3096) и недостижимая ветка в `ChangeOnOff` (проверяется колонка 7, чекбокс в колонке 8).

**4. Индексный механизм недоиспользован.** `BotTabIndex` (3363 строки, авто-сборка формулы, нормализация, четыре типа весов) применяют всего 8 роботов. Это самый мощный инструмент анализа в проекте, и он почти пустует.

**5. Тестер не воспроизводит три вещи**, критичные для целых категорий: очередь заявок (группа L), размерность лотов (группа I — в тестере лот = 1), стоимость плеча и налоги (поэтому существуют `PayOfMarginBot` и `TaxPayer`). Для групп L и I бэктест в OsEngine даёт заведомо оптимистичную картину.

**6. Нет юнит-тестов на торговую логику.** `project/Tests/` — 6 exe-заглушек, `AutoTestBots/ServerTests` (38 файлов) проверяет API заявок, но не стратегии. Единственный способ проверить робота — прогнать его через тестер/оптимизатор на Windows.

**7. Русская и английская локализация описаний не всегда совпадают** с фактическим кодом: `TwoLegArbitrage` в английском описании продаёт «когда RSI поднимается выше уровня oversold» — там должно быть overbought.

## Что выбрать под задачу

- **Начать с нуля** → `Lesson1HelloWorld` … `Lesson9Bot5`, затем `SmaTrendSample` и `RsiTrade` как канонические шаблоны.
- **Торговать MOEX акции в тренде** → `SpeculantSetMomentumAdaPc` или `SpeculantSetAtrKeltner` (два скринера, раздельные лонг/шорт, фильтры волатильности) либо `SectorsSetBollingerMomentum` (ротация по секторам).
- **Торговать флэт на MOEX** → `GridBollingerScreener` (ADX-фильтр волатильности) или `GridScreenerAdaptiveSoldiers`.
- **Портфельное инвестирование** → `RebalancerByMomentum` + `TmonRebalancer` как обязательная парковка свободных денег.
- **Низкорисковый арбитраж** → `SyntheticBondsCurveArbitrage`, но только после проверки размерности лотов на реальном подключении.
- **Дивидендные истории** → `DividendCaptureScreener` (захват) или `ShortBadDividends` (игра на слабом дивиденде).
- **Наблюдать, а не торговать** → `MonitorVolume` + `MonitorImpulse` + `LiquidityAnalyzer` для проверки глубины перед выбором бумаг.
- **Свой индикатор в бою** → `OnScriptIndicators/` как шаблон подключения.
- **Ручная торговля с журналом** → `Engines/CandleEngine` или `ScreenerEngine`.
- **Крипта** → `ArbitrageFunding` / `TakeFunding` (фандинг), `Fisher` (стакан).
